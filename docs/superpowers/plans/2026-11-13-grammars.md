# gositter-rs grammars (gengrammar, tables, scanners) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generate the parse tables and lexers of all 21 gositter grammars from their pinned `parser.c` files with a Rust port of gositter's `cmd/gengrammar`, and hand-port the 15 external scanners, so that the runtime stream can reach all 1,423 goldens on amd64 and arm64.

**Architecture:** `gengrammar` (a binary crate) reads the C subset of each `parser.c`, checks its sha256 against `grammars/grammars.lock`, and writes per grammar one little-endian `tables.bin` (read with `include_bytes!` through small typed views) plus generated Rust for constants, names and the lexer. A `gen` Dockerfile target downloads the 21 grammar modules from the Go module proxy and runs gengrammar; its output is committed, and the `test` stage regenerates it and fails on any diff. Two Go oracles built from the gositter v0.2.0 module (no C, `CGO_ENABLED=0`) prove the tables byte for byte and the lexers by trace digest. The lexer form (generated `match` code or a data table) is chosen by a CI benchmark on bash, cpp and verilog before the other 18 grammars are generated.

**Tech Stack:** Rust 1.99.1, edition 2024, std only (no third-party crates). Go 1.27 inside Docker for the oracles only. BuildKit on the ARC runners.

**Spec:** graphify-rs `docs/superpowers/specs/2026-11-12-graphify-rs-design.md` (sections 2, 3 "gositter-rs", 7 and 12), and the master plan `docs/superpowers/plans/2026-11-12-graphify-rs-master.md` (Global Constraints, Task 4). Read both from graphify-rs `main`: `git -C <graphify-rs> show origin/main:<path>`.

**Oracle sources (read only):** gositter v0.2.0 (7a27b30): `cmd/gengrammar/{main,ctok,parse,emit,run}.go`, `cmd/gengrammar/gengrammar_test.go`, `cmd/gengrammar/check/` (C verifier: its checks are the model for the Go oracles), `grammars/grammars.lock`, `grammars/internal/cchar/`, `grammars/<g>/scanner.go`, `scanner_test.go`, `reset_test.go`, `api.go`.

## Review Focus

1. **A `parser.c` construct gengrammar reads wrongly but without an error** (designators that go backwards, a struct field missing, a table with a trailing zero run). Expected: the table bytes still equal gositter's. Pinned by the table oracle in Task 6 on all 21 grammars, plus `miniC` unit tests.
2. **Lookahead values at the edges of a lex condition**: -1, 0 (end of input), 0x7F/0x80, 0xFFFF/0x10000, 0x10FFFF, and each literal ±1. Expected: the same accept, symbol and advance trace as gositter. Pinned by the lex oracle (Task 8 on four grammars, Task 9 Step 3 on all 21; points from gositter's `check/main.go:399-440`).
3. **A scanner's serialize buffer at exactly the 1,024-byte bound** (one byte under, at, one over). Expected: the same byte count and bytes as gositter, 0 where gositter gives 0. Pinned by each scanner's `*Limit*` tests in Tasks 9-11.
4. **The same input on linux/arm64 and on x86_64** where a scanner reads back a `char` (bash heredoc end, ruby heredoc end, hcl `charMax`). Expected: the arm64 tree follows unsigned `char`, the x86_64 tree follows signed `char`, as gositter. Pinned by `cchar` tests and `bash::heredoc_end_char` in the `arm64` stage.
5. **A stale committed table** after a gengrammar change or a lock change. Expected: `test` fails, and names the file. Pinned by the regeneration diff in Task 5 and its negative proof step.

Generated files are exactly `grammars/<g>/mod.rs`, `grammars/<g>/lex.rs` and `grammars/<g>/tables.bin` (plus `lex.bin` if the table form wins). `lex.rs` writes symbols as numbers with the C name in a comment, so a test can include it with `#[path]` before its grammar is in `lib.rs`. `grammars/lib.rs` is hand-written: a grammar is added to it only when it compiles (its scanner exists), so generated modules of later grammars can be committed early as data.

Generated files are never formatted: every declaration of a generated module (`pub mod <g>;` in `lib.rs`, `mod lex;` in a generated `mod.rs`, a `#[path]` include in a test) carries `#[rustfmt::skip]`, so `cargo fmt --all --check` in `ci` and a local `cargo fmt` leave them alone, and the `gen-check` byte diff stays meaningful. Task 5 Step 4 proves it: a local `cargo fmt` changes no generated file.

## Interface needed from the runtime stream

The runtime stream defines these in its plan PR. This plan proposes the shapes below; the runtime plan decides. Tasks 1-7 and 11 need none of them. Tasks 8-9 need only the lexer trait: it is this stream's trait (`gositter_grammars::lex::LexOps`), and Task 8 starts only after the runtime accepts its shape (a concrete `Lexer` would change inlining and so the Task 9 result). Tasks 10, 12 and 13 wait for the rest.

- **Crate names.** Runtime crate `gositter` (root); this plan adds `gengrammar` and `gositter-grammars` as workspace members. `gositter-grammars` depends on `gositter` (path `..`). The runtime's regress runner dev-depends on `gositter-grammars` and lives in the runtime's `tests/`, not in a third crate (coordinator condition c).
- **Table views.** `Language` holds tables as views over `&'static [u8]` from `include_bytes!`, decoded with `from_le_bytes` on access: `U16s`, `U32s`, `Bools`, `ParseActions` (8 bytes), `LexModes` (6 bytes), `SymbolMetadata` (1 byte), `MapSlices` (4 bytes), `FieldMapEntries` (4 bytes). Byte layout: Task 4. Names and strings are `&'static [&'static str]`.
- **Lexer trait for generated lexers.** `lookahead() -> i32`, `eof() -> bool`, `advance(skip: bool)`, `advance_run(set: &'static [bool; 256], skip: bool)`, `mark_end()`, `set_result_symbol(sym: u16)`. Generated `lex` and `lex_keywords` are generic over it, so the oracle mock (Task 8) and the runtime `Lexer` both drive them.
- **Scanner trait.** `scan(&mut self, l: &mut Lexer, valid: &[bool]) -> bool`, `serialize(&self, buf: &mut [u8; SERIALIZATION_BUFFER_SIZE]) -> usize`, `deserialize(&mut self, buf: &[u8])`, `reset(&mut self) -> bool` (default `false`: no Reset; bash, cpp, hcl and python return `true`). `SERIALIZATION_BUFFER_SIZE = 1024`. Scanners also call `get_column() -> u32` and `is_at_included_range_start() -> bool`. Constructor in `Language`: `fn() -> Box<dyn ExternalScanner>`.
- **`Language: Clone`.** The reset tests swap the scanner constructor to capture the scanner (`language.ExternalScanner.New = …` in Go); in Rust a test clones `*language()` and sets its constructor field, because the `static` cannot change. The parser must take `&Language` from any lifetime the test can give (or `&'static` via `Box::leak` in the test).
